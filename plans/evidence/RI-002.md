## Scope delivered

RI-002 adds a governed scientific-ingestion path on top of the RI-001 canonical
evidence kernel. It does not replace or silently migrate the existing Research
Intelligence inbox.

- Uploaded bytes enter a content-addressed filesystem quarantine before parsing.
- The declared media type, filename suffix, magic signature, bounded size, page
  count, expansion ratio, active PDF content, malware signature, and
  instruction-injection patterns are validated before publication.
- PDF recovery uses strict `pypdf` parsing. A scanned PDF can use only an explicitly
  supplied OCR adapter that declares `network_access = False`.
- A pluggable malware-scanner protocol separates the built-in signature gate from a
  future production antivirus implementation.
- Recovery emits ordered section, paragraph, table, figure, equation, citation, and
  note objects with page and line coordinates, parent relationships, extraction
  method, and confidence.
- A configurable confidence floor sends uncertain recovery to remediation instead
  of canonical publication.
- Canonical source, edition, artifact, and scientific objects receive deterministic
  UUIDs and are published in one database transaction. Any publication exception
  rolls back all canonical writes and leaves the artifact in quarantine.
- Coordinate replay reopens the retained artifact, repeats recovery, and verifies
  object type, page, line interval, and exact recovered text through the RI-001
  access-class hook.
- Authenticated create, inspect, process, and replay endpoints are locked by an
  OpenAPI surface snapshot. No ingestion delete or arbitrary parser endpoint exists.
- A bounded worker claim function selects one eligible ingestion job with
  `FOR UPDATE SKIP LOCKED`; scheduling and retry policy remain caller-owned.

## Stage and failure contract

Each job retains a bounded stage report without raw document text. Successful jobs
record quarantine, scan, extract, recover, validate, and publish stages with artifact
digest, byte count, scanner/parser identity, page/object counts, OCR status, warnings,
and timestamps.

| Failure class | Terminal handling | Canonical writes |
|---|---|---|
| Digest, size, type, archive, active content, or malware mismatch | Rejected in quarantine/scan | None |
| Corrupt parser output or unsafe/undeclared OCR | Rejected | None |
| Missing approved OCR or low confidence | Remediation required | None |
| Instruction-injection content | Rejected as untrusted document data | None |
| Database/publication exception | Remediation required after transaction rollback | None |

The quarantine object is immutable and digest-verified when stored and read. Object
paths are derived only from lowercase SHA-256 values and must resolve beneath the
configured evidence root. Files and directories are created with restrictive modes.

## Security and authority boundary

Documents are always treated as untrusted data. They cannot choose a parser, command,
path, scanner, OCR adapter, access policy, or publication identity. RI-002 uses no
shell and defines no command-execution surface. The default parser path requires no
network. Authentication and RI-001 project/access-class checks remain mandatory for
canonical reads and coordinate replay.

The built-in malware scanner is deliberately narrow and is not a claim of production
antivirus coverage. Production rollout requires an approved scanner adapter and an
approved offline OCR adapter where scanned documents are admitted.

## Rollback and limitations

The RI-002 migration may be downgraded before ingestion-job writes. Published RI-002
objects are canonical RI-001 evidence and must not be deleted by a rollback. After
writes exist, rollback must retain the ingestion table and object bytes or use a
reviewed compatibility migration.

RI-002 does not bulk-import the existing inbox, backfill legacy document bundles,
build embeddings or lexical/vector/graph projections, provide corpus-management UI,
perform external source surveillance, or authorize model-authored research decisions.
Those remain RI-003, RI-005, and later packages.
