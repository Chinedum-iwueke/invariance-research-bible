## Scope delivered

RI-003 adds a canonical query service over RI-001 evidence objects recovered by
RI-002. Existing legacy knowledge search remains compatible and is not silently
rewritten or backfilled.

- A versioned `canonical-scientific` projection contains only canonical scientific
  objects with retained content text.
- Exact retrieval matches canonical UUIDs, content digests, immutable aliases, and
  exact text spans.
- Lexical retrieval uses deterministic normalized term-frequency cosine scoring and
  expands underscored/hyphenated scientific identifiers into natural-language parts.
- Vector retrieval uses a deterministic, network-free 64-dimensional signed hashing
  projection with a small declared quantitative synonym map.
- Graph-assisted retrieval expands through canonical evidence lineage edges.
- `rrf-v1` combines only requested channels using reciprocal rank with `k = 60`.
  Ties resolve by canonical UUID, making repeated ranking deterministic.
- Each result advertises channel scores and ranks, canonical digest, scientific type,
  access class, schema version, exact page/line coordinates, and a replay path.
- Query filters cover project, scientific type, retrieval channel, projection version,
  and compatible canonical evidence schema versions.
- Project and access-class filters apply before scoring. Every selected hit is then
  re-read through the RI-001 canonical access hook and its digest is compared with the
  projection before text or citation data is returned.
- The projection corpus digest binds object UUID, content digest, evidence schema,
  project, access class, aliases, graph edges, and projection version.
- Missing, incompatible, stale, or canonically mismatched projections fail closed
  with `409`; they are never served opportunistically.
- An authenticated API exposes rebuild, status, query, and exact coordinate replay.
  A typed asynchronous HTTP client sends bearer authentication, parses strict models,
  supports clean shutdown, and redacts its token from errors.

## Security and compatibility boundary

Queries cannot provide SQL, vector values, graph edges, ranking code, or executable
configuration. Projection builders read canonical database records only and require no
network. Compatibility is explicit: unsupported evidence or projection versions are
filtered or rejected. Protected content cannot appear merely because a projection row
exists; canonical access is checked again immediately before response construction.

The local hashed-vector channel is an auditable baseline, not a claim of learned
semantic embedding quality. A later embedding adapter must be versioned, evaluated,
network-governed, and replaceable without changing canonical evidence.

## Rollback and limitations

Both RI-003 tables are derived projections. They may be dropped and deterministically
rebuilt from canonical evidence. Canonical RI-001/002 objects and quarantined artifacts
are never removed by retrieval rollback. After RI-003 is in use, rollback should retain
the alias timestamp repair or move it into a reviewed compatibility migration.

RI-003 does not bulk-import legacy inbox bundles, generate model-authored decisions,
build contradiction/belief dossiers, expose retrieval in Mission Control, establish
production latency/scale SLOs, or deploy learned domain embeddings. Those remain
RI-004, RI-005, and later work.
