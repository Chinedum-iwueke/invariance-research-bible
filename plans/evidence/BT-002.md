## Implementation

BT-002 extends `bt.research_data`; it does not create another lake or dataset loader.
The new contract binds explicit Parquet inputs to BASE-002 canonical identity,
partition/content digests, UTC event-clock semantics, availability policy and cutoff,
point-in-time membership, append-only correction lineage, access classification and a
deterministic validation report. Its CLI builds derived JSON manifests outside source
partitions and replays their bytes before execution.

The JSON Schema is `immutable-dataset-snapshot-v1.0.0`. Missing observations remain
missing and gap intervals are visible. Duplicate keys, future availability, invalid
membership timing, late corrections, path escape, changed partitions, identity drift
and manifest-digest drift fail closed.

## Claim boundary

BT-002 qualifies explicitly selected snapshots. It does not certify the whole lake,
populate missing vendor-correction history, grant entitlements, publish to Hermes, or
produce an atomic run bundle. DATA-001 through DATA-003 own lake-wide population and
operations; BT-003 and BT-008 own run finalization and RI publication.
