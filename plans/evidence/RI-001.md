## Scope delivered

RI-001 implements the canonical evidence identity and schema kernel without migrating
legacy records or implementing ingestion, embeddings, retrieval, or UI.

- `canonical-identity-v1.x` remains the common ADR-0005 identity envelope.
- `canonical-evidence-v1.x` independently versions the object payload contract.
- PostgreSQL stores canonical objects, append-only aliases, direct lineage edges, and
  audit events; search indexes and graphs remain rebuildable future projections.
- Create/read/list/lineage APIs require orchestrator authentication. No update or
  delete API exists.
- Service access hooks enforce project and `public`/`internal`/`restricted`/
  `protected` classification before payload return or write.
- An `EvidenceObjectStore` protocol separates immutable binary storage from canonical
  PostgreSQL metadata without selecting a storage vendor.

authority conflation, malformed digests, invalid validity intervals, and unsupported
identity or object major versions are rejected by strict Pydantic/OpenAPI contracts.

## Integrity and access behavior

- Non-artifact payload digests are recomputed from canonical JSON before writes.
- Artifact byte digest must exactly match the envelope content digest.
- Re-registering an identical object is idempotent; changing its bound identity or
  payload conflicts.
- Producer identity must appear as an immutable alias. Alias ownership is unique.
- Missing, cross-project, or more-restricted lineage references fail closed.
- A successor must retain project/type, change content version, and point to the
  superseded UUID. Earlier objects remain unchanged.
- Create and read events are attributable without recording credentials or payloads.

## Rollback and limitations

The migration may be downgraded only before canonical writes. Once canonical objects
exist, rollback must preserve the tables/readers or use a reviewed compatibility
migration. Legacy Hermes records remain in their existing tables and are not
backfilled by RI-001.

RI-001 does not recover documents, store production binary artifacts, build lexical,
vector, or graph projections, provide citation replay, expose a Mission Control UI,
or authorize research promotion or capital mutation. Those remain RI-002 and later
work packages.
