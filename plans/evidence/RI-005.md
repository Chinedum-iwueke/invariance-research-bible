## Scope delivered

RI-005 adds an operational boundary around RI-001 through RI-004 without granting
corpus content, recovery tooling, or derived projections any governance authority.

- Ingestion rejects indirect instruction attacks, policy overrides, secret-file
  requests, approval spoofing, tool/shell coercion, and system-instruction claims in
  both source content and source metadata.
- Rejected artifacts remain content-addressed quarantine evidence. Immutable findings
  retain only finding code, stage, severity, disposition, and bounded remediation;
  they contain no source text, filename, extracted protected content, or credential.
- Prometheus exposes aggregate ingestion status, finding code counts, projection age,
  backup age, restore-proof age, canonical object count, and referenced artifact bytes.
  Labels exclude project, filename, access class, and content.
- Corpus health reports canonical objects, storage bytes, backlog, rejections,
  findings, missing artifacts, projection status/age, backup/restore age, and each
  initial SLO independently.
- A portable `corpus-backup-v1.0.0` manifest binds canonical objects, aliases, lineage
  edges, artifact references, project corpus digest, and manifest digest. Repeating an
  unchanged backup is idempotent.
- Backup fails if a referenced artifact is absent. Restore verifies manifest schema,
  project, manifest digest, corpus digest, referenced artifact presence, and artifact
  bytes before making the corpus usable.
- Restore requires literal confirmation and an empty project corpus. Canonical
  supersession links are applied after identity insertion. Derived RI-003 projections
  are rebuilt from restored canonical evidence rather than restored from backup.
- Queue recovery only requeues stale jobs whose content-addressed source exists.
  Missing sources remain in remediation and emit an attributable security finding.
- Every restore, projection rebuild, and queue repair records the requester, bounded
  evidence, duration, status, and evidence digest.
- A typed asynchronous client authenticates all calls, supports clean shutdown, and
  removes its token from errors. The operator runbook defines backup, recovery,
  restore-drill, SLO, security-response, and rollback procedures.

## Security evaluation

The synthetic adversarial suite covers OWASP-style indirect prompt injection,
instruction hierarchy spoofing, approval spoofing, secret exfiltration requests,
tool execution coercion, malicious metadata, active PDF content, archives, malware,
parser limits, invalid containers, missing artifacts, corrupt manifests, non-empty
restore targets, protected metric-label leakage, and client token leakage.

Corpus evidence cannot authorize, approve, execute, widen permissions, choose a restore
target, supply a filesystem path, issue SQL, or define parser commands. All mutation
routes require orchestrator bearer authentication and strict request models.

## Initial SLO contract

- all canonical artifact references are available;
- retrieval projection digest matches the canonical corpus;
- backup age is at most 24 hours;
- successful restore-proof age is at most 30 days;
- ingestion/remediation backlog remains below 100 jobs.

These are initial operating objectives, not observed production SLO attainment.

## Rollback and limitations

The additive downgrade removes only RI-005 finding, backup-registry, and recovery-run
tables. It does not delete canonical evidence, quarantined artifacts, frozen dossiers,
or object-store bytes. Operational evidence must be exported before downgrade.

The local filesystem object store is a content-addressed adapter, not proof of off-host
durability. RI-005 does not deploy VM2 schedules or alerts, perform a production restore,
prove deletion propagation across backups, qualify production load/latency, install an
external antivirus engine, deploy production OCR, or begin source surveillance. Those
remain deployment work and later roadmap scope, including RI-006.
