# Chapter 17 — From Minimal Team to Mature Organization

Agent architecture should grow with evidence and operational need, not simulated organizational complexity.

## 17.1 Minimal team

Begin with one research worker, one independent evaluator path, one knowledge curator, and deterministic experiment, memory, risk, and deployment services. Humans retain approval and incident authority.

## 17.2 Expansion triggers

Add specialization when workload, data class, tool risk, evaluation evidence, or separation of duty requires it. New roles receive clear interfaces and ownership. Duplicate personas without distinct contracts add coordination cost.

## 17.3 Maturity stages

Progress from assisted drafting, to bounded tool use, to orchestrated task graphs, to monitored autonomous sessions inside budgets, and finally to mature multi-service operation with independent evaluation and recovery. Capital and production authority remain external throughout.

## 17.4 Acceptance

Book IX is accepted when agents are replaceable; roles, runtimes, permissions, and tasks are separate; tools enforce authority; context preserves provenance; review is independent; workflows terminate; evaluation covers actions; security contains cognitive compromise; deployment is observable; and improvements pass ordinary governance.

> **Agent rule B9-AG17 — Organization follows proven interfaces**  
> Add agents only when a bounded responsibility, enforcing service boundary, evaluation, and accountable owner justify the new coordination surface.
