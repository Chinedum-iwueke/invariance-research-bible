# Chapter 17 — Migration to the Target Laboratory

The public repository is a substantial experimental substrate, not the final institutional laboratory. Migration should preserve verified behavior, close evidence gaps, and avoid a rewrite that destroys accumulated tests and artifact compatibility.

The controlled [current/target/migration diagram](../../../architecture/diagrams/implementation-migration.md) and [company engineering roadmap](../../../plans/COMPANY_ENGINEERING_ROADMAP.md) place this laboratory migration after the Research Intelligence identity foundation and governed agent reliability, while allowing baseline defect repair to proceed in parallel.

## 17.1 Preserve

The target retains the explicit classic-engine boundaries; typed market and trading events; deterministic configuration practices; instrument-aware risk; visible costs; audit layers; run bundles; hypothesis and grid machinery; truth validation; research-data extraction; and extensive regression tests.

The single-strategy engine remains a reference kernel even if a future same-clock portfolio simulator is introduced. Its golden runs provide differential evidence.

## 17.2 Correct the baseline record

First, documentation is reconciled with code. The root V1 exclusions, portfolio plan, dashboard descriptions, and execution claims receive versioned status labels. Public entry points are enumerated, experimental surfaces are marked, and every artifact has a registered schema or an explicit legacy contract.

Dependency locking and supported environment matrices are added. The full suite, lint, type checks where adopted, security scans, and minimal golden runs execute at release pins. QG-011 records exact results.

## 17.3 Close scientific contracts

Second, run identity becomes content-derived; datasets use immutable manifests and content hashes; fit artifacts and availability times become mandatory for learned or fitted representations; search histories preserve all attempts; and run bundles gain digest manifests and atomic finalization.

Truth validation expands to every enriched source timestamp, schema compatibility, artifact digest, tier assertion, and accounting identity. Failure, invalidity, negative evidence, and infrastructure interruption retain separate states.

## 17.4 Integrate without conflating

Third, Hermes submits authorized experiment contracts and receives typed lifecycle events. Research Intelligence ingests validated bundle references and publishes compatible projections. Books VII and VIII supply versioned portfolio and execution policies. Book IX’s agents use these interfaces without becoming authorities. Book X deploys isolated workers, stores, queues, secrets, observability, and recovery.

No service gains promotion authority by hosting a convenient endpoint.

## 17.5 Extend simulation

A same-clock multi-strategy engine, richer corporate actions, robust contract rolls, tick and order-book replay, queue and impact models, and broader venue certification are extensions or deferred capabilities. Each enters through a contract, independent test oracle, and compatibility plan.

The current sleeve-based portfolio runner remains useful for capital-isolated aggregation. It should not be relabeled as a unified matching engine.

## 17.6 Acceptance

The target laboratory is accepted when it can reconstruct a registered experiment from immutable identities; enforce causal data and fit boundaries; execute repeatably across supported environments; reconcile events to accounting and metrics; preserve every attempt and failure; publish validated evidence without promotion; replay operational journals; and demonstrate recovery under injected failure.

Profitability is not an infrastructure acceptance criterion.

> **Laboratory rule B5-LR17 — Migration advances evidence, not branding**  
> A capability changes status only when its contract, implementation, tests, operational evidence, and limitations justify the new claim class.
