# Chapter 15 — Opportunity, Mechanism, Representation, and Search Graphs

Discovery consumes graph projections to connect unresolved questions, observations, mechanisms, representations, experiments, and search history. Book III owns the canonical evidence core and projection semantics. Book IV owns how these views support discovery without becoming automatic agenda or alpha engines.

## 15.1 Opportunity view

The Opportunity view links knowledge gaps and questions to possible scientific, operational, portfolio, or strategic value; required evidence; feasibility; cost; risk; and dependencies. These values are scoped estimates with authors and review dates.

An opportunity node cannot allocate resources or become a candidate. It supports a program proposal to Hermes.

## 15.2 Mechanism view

The Mechanism view links actors, constraints, processes, observables, predictions, alternatives, boundary conditions, and evidence. Observed, assumed-causal, predicted, and contradicted edges remain visually distinct.

Discovery uses the view to generate discriminating tests and detect shared explanations. Path existence does not establish a mechanism.

## 15.3 Representation view

The Representation view links source observations, transformations, fit state, invariants, information loss, causal availability, questions, models, and failures. It helps retrieve transforms with compatible semantics and prior leakage defects.

Predictive performance is one edge among many. The view cannot rank representations universally across questions.

## 15.4 Search view

The Search view projects declared spaces, configurations, proposals, runs, result exposures, selection, early stopping, and candidate lineage. It supports denominator reconstruction, duplication detection, and selection-aware evaluation.

> **Discovery rule B4-DR15 — Graphs propose paths, not conclusions**  
> Discovery graph traversals can create questions and retrieve evidence; every resulting hypothesis, novelty claim, priority, or mechanism remains a typed object requiring review and registration.

## 15.5 Cross-projection queries

Cross-projection queries can ask which open questions have an untested mechanism and an available representation, which candidate families share a failed data dependency, or which anomalies resemble prior implementation defects. The query manifest records projection versions and access filters.

Agent-generated multi-hop explanations remain proposed inferences until their supporting edges and scope are reviewed.

## 15.6 Access and lifecycle

Protected sources constrain nodes, edges, neighborhoods, counts, and embeddings. A discovery worker receives only the graph slice authorized by its charter. Projection rebuild, invalidation, and deletion propagate from Book III’s core.

Graph effectiveness is evaluated through successful prior-work recovery, useful gap identification, reduced duplication, and reviewed hypotheses—not graph size or centrality.
